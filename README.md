# v1.0.0 归档提交

这是一个**独立的归档提交**：它不属于任何分支，也不在 `main` 的历史上，只为 tag `v1.0.0` 提供一个准确的落点。

## 为什么单独做一个提交

1.0.0 的源码从未纳入本仓库的版本管理——仓库最早的提交（`a847522`）已经是 2.0.0，因此无法为 1.0.0 提供真实的源码归档。

如果直接把 `v1.0.0` 打在 `a847522` 上，GitHub Release 页面自动生成的 `Source code (zip)` / `(tar.gz)` 会装着 2.0.0 的源码却标成 v1.0.0，属于误导。所以这里改为只归档当天留存下来的两个二进制构建。

## 1.0.0 的状态

1.0.0 是最早跑通的构建，核心处理链路已经成形：

```text
JSON 配置 -> ItemComponentManager -> Mixin 判断来源 -> 修改 ItemStack 数据组件
```

源码可以成功构建，Fabric 服务端开发环境也完成了 Mixin 加载与模组初始化。但功能上有许多错误和不完善之处，**不建议用于任何实际存档或服务器**。请改用 2.0.1。

## 已知瑕疵

以下清单并不完整。

### 配置与权限

- 客户端 GUI 没有网络协议。连接专用服务器时，它修改的是客户端配置而不是服务器配置，也没有任何服务端权限校验。
- 配置重载前没有清空旧 Map，因此从 JSON 中删除的条目可能在 `/originlore reload` 之后继续存在。

### 组件写入正确性

- 所谓随机"攻击伤害"错误地写入 `DataComponentTypes.DAMAGE`；该组件实际表示物品已有的耐久损耗，并不会改变攻击力。
- 最大堆叠缺少 1-99 校验，同时允许最大耐久和大于 1 的堆叠数并存，会产生 Minecraft 判定为无效的组件组合。

### 规则合并

- 战利品和合成物品可能先应用默认规则、再叠加来源规则。未填写的字段会从默认规则泄漏，三个标签并非真正独立。
- 配方覆盖不完整：特殊原版配方、锻造纹饰，以及不继承这些原版类的模组配方都不会被处理。

### 管理界面

- 编辑器直接修改配置对象。切换标签后点击取消，部分修改仍可能在内存中生效；滚动重建界面又可能丢失尚未收集的输入。
- 随机堆叠、随机耐久已经存在于配置模型中，却没有对应的 GUI 控件。

### 其他

- `fabric.mod.json` 的 `authors` 字段仍是 Fabric 示例模组的占位值 `"You"`，未替换。
- 没有任何自动化测试覆盖。
