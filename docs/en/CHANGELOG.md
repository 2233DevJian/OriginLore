# OriginLore Changelog

## v2.0.1 (2026-09-02)

### Fixed

- Items that other mods put directly into a player's inventory no longer miss their source metadata. They are now correctly classified as `UNKNOWN` and can be adopted in bulk with an `UNKNOWN` rule. Previously they only picked up their rules when the player rejoined or the inventory was refreshed, so anything eaten, split or crafted in between missed the rules permanently.
- The path that hands out an item into a specific slot did not work at all. Both `insertStack` overloads and `setStack` now behave identically: all three entry points apply base rules and source rules.

### Behaviour notes

- An item that already carries a definite source keeps it when it passes through the `UNKNOWN` fallback; it is never downgraded.
- A single hand-out goes through component application twice (`insertStack(ItemStack)` delegates internally to the slot-taking overload). The second pass is skipped because neither the source nor the config revision changed. Random variants are not re-rolled and already-generated variant identities are preserved.
- Existing dedicated entry points are unchanged: `/give`, loot tables, crafting table, furnace, stonecutter, smithing table and anvil.

### Tests

- Added one GameTest covering `insertStack(ItemStack)`, `insertStack(int, ItemStack)` and `setStack(int, ItemStack)` separately, asserting that both base rules and the `UNKNOWN` source rule take effect. GameTest count went from 11 to 12.
- Under Fabric Loader 0.19.2 and 0.19.3, all 18 JUnit tests and all 12 GameTests pass.

## v2.0.0 (2026-09-01)

### Server-authoritative architecture

- Config upgraded to schema v3, with migration from the old flat format, atomic writes, corruption fallback and a monotonically increasing revision.
- The admin GUI moved to server snapshots plus transactional commits; clients below permission level 2 can neither read nor modify the config.
- Network protocol v2 uses GZIP, bounded fragmentation, upload timeouts, version conflict checks and bounded responses.
- Regular players need no client mod at all — data components generated by the server are usable by a vanilla client.

### Sources, variants and components

- Added 14 unified source types, concrete loot table / recipe matching and an `UNKNOWN` fallback.
- Added three-tier merging of base, source and weighted random variant rules; variants and random values are persisted after the first roll.
- Source identity, config revision and the original component patch are stored under `minecraft:custom_data.originlore`.
- Supports name, lore, rarity, stack size, durability, fire resistance, enchantments, food, status effects, attributes, tools, model data and tooltip control.
- Added advanced data component JSON editing, with invalid combinations rejected by the Minecraft component codec and the `ItemStack` validator.
- Removing a managed field restores the explicit set, explicit removal or item default recorded before first adoption.

### Generation and hot refresh

- Source entry points cover LootTable, block/entity drops, commands, crafting table, smelting, stonecutting, smithing and the anvil.
- Furnaces, smokers and blast furnaces pause after finishing each OriginLore item and resume only once the output is taken, rolling the next item against the newest weights so a single output slot never mixes random variants.
- Smelting output of the same variant stacks normally once OriginLore bookkeeping (source, recipe, config revision) is ignored; different variants stay isolated.
- Added the player inventory and standard inventory fallbacks so unrecognised mod entry points land safely in `UNKNOWN`. (The player inventory fallback only actually took effect from 2.0.1 onwards — see above.)
- After a config save, online players, ender chests, equipment, loaded containers, block entities and item entities are refreshed incrementally.
- Lazy refresh on player login, chunk/entity load and inventory change; unloaded chunks and offline saves are never scanned.

### GUI and quality

- Fixed a client crash when coexisting with CAD Editor 0.1.0: clicking "Add" or entering the JSON editor hit its incompatible vanilla multi-line text mixin. All multi-line input now uses OriginLore's own widgets; no third-party mod is modified.
- Fixed the style buttons at the bottom of the text rule page overlapping the Save and Cancel buttons at high GUI scale / short window heights.
- Fixed the "current variant weight" label overlapping the item ID field in the rule editor, and added spacing for the weight summary and page tabs on narrow windows.
- Added three-tier rule editing, registry tab completion, Text JSON styling, and food effect, enchantment, attribute, tool and advanced component editors.
- Editors use transactional copies and support cancelling, disconnect protection, server-side validation errors and automatic revision updates after saving.
- Once a variant is selected, the main editor shows the weight field and live probability directly; `80` / `20` and `80%` / `20%` are both accepted, and weights can be hot-modified at any time.
- Fixed text bleed-through, cramped line height and screen-edge misplacement in dropdowns and registry completion popups; popups now expand up or down automatically, clip long text and support mouse wheel selection.
- Source types are fully localised in the GUI while the stable English enum values used by the config and network protocol are preserved.
- Added a Chinese user manual covering basic rules, sources, random variants, food effects, tools and weapons, and advanced components.
- The mixin list contains only real mixins and is pinned to Minecraft 1.21.1 method signatures with a production refmap.
- Added config, network, merging, migration, restoration, variant stability, codec and GameTest coverage.
- Minimum supported Fabric Loader raised to 0.19.2; 0.19.3 continues to be used for quick regression runs.
